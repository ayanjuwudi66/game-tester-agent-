# 多模态文件解析 Skill

## 功能概述
此skill根据文件类型调用适当的解析方法，提取文档中的文本内容、表格数据和图片信息。

## 使用场景
在 `file-scanner` skill扫描完成后，调用此skill对每个文件进行内容解析。

---

## ⚠️ 解析核心原则（强制遵守）

### 原则1：完整描述可见内容 + 合理推断标记

```
✅ 必须做：
- 完整描述肉眼可见的所有UI元素（按钮、输入框、图标、列表等）
- 转述原文档中明确写明的内容
- 对图片中的元素进行客观描述
- 【重要】对于可见UI元素暗示的功能，允许推断但必须标记【待确认】

⚠️ 推断规则：
- 看到搜索框 → 可以输出"搜索功能【待确认】"
- 看到密码输入框 → 可以输出"密码设置功能【待确认】"
- 看到刷新图标 → 可以输出"刷新功能【待确认】"

❌ 禁止：
- 完全凭空"脑补"图片中看不到任何线索的功能
```

**示例**：
- ❌ 错误："该页面应该有分享到微信功能"（图片中无任何分享相关元素）
- ✅ 正确："图片显示一个输入框，placeholder为'请输入手机号'"
- ✅ 正确："图片显示一个搜索图标，推断有搜索功能【待确认】"

### 原则2：置信度标注

对于解析内容的置信度，必须进行标注：

| 标注 | 含义 | 使用场景 |
|------|------|----------|
| （无标注） | 高置信度，内容清晰可见 | 文字清晰、元素明确 |
| `【待确认】` | 基于可见元素的合理推断 | 看到UI控件推断其功能 |
| `[?]` | 低置信度，内容模糊或不确定 | 图片模糊、文字不清、元素含义不明 |
| `[无法识别]` | 无法识别的内容 | 完全看不清、无法判断 |

### 原则3：来源标注

每段解析内容必须标注来源类型：

| 来源标注 | 含义 |
|----------|------|
| `[文字]` | 来自文档正文文字 |
| `[表格]` | 来自文档中的表格 |
| `[图片]` | 来自图片解析 |
| `[图片OCR]` | 来自图片中的OCR文字提取 |
| `[图片推断]` | 基于图片可见元素的合理推断 |
| `[CSS注释]` | 来自CSS文件中的注释 |
| `[CSS类名]` | 来自CSS文件的类名/选择器 |
| `[CSS样式]` | 来自CSS文件的样式属性值 |

## 支持的解析类型

### 1. Word文档 (.docx)
- 提取正文文本
- 识别和提取表格内容
- 识别文档中的图片

### 2. PDF文档 (.pdf)
- 提取文本内容
- 识别表格结构
- 提取嵌入图片

### 3. 纯文本文件 (.txt, .md)
- 直接读取文本内容
- 识别Markdown格式结构

### 4. 图片文件 (.png, .jpg, .jpeg, .gif, .bmp, .webp)
- 使用视觉模型分析图片内容
- 提取图片中的文字（OCR）
- 描述图片内容

### 5. 🆕 CSS设计稿文件 (.css) - Figma导出
从 Figma 导出的 CSS 文件（"Copy as Code" → "CSS (All Layers)"）是结构化的交互设计数据源。

**CSS 文件的优势（相比图片）**：
| 对比项 | 图片（PNG） | CSS文件 |
|--------|-------------|---------|
| 功能遗漏 | 容易遗漏（多模态识别有限） | 不遗漏（所有图层都有） |
| 幻觉风险 | 存在幻觉 | 无幻觉（客观数据） |
| 交互说明 | 需要推断 | CSS注释中明确写明 |
| 视觉规范 | 需要估算 | 精确数值 |

**CSS 解析重点**：
- **CSS 注释**：包含组件名称、中文文案、交互规则说明
- **类名结构**：反映页面层级和组件关系
- **样式属性**：颜色、字体、尺寸、间距等视觉规范

## 执行流程

### 步骤1：接收文件清单
从 `file-scanner` 的输出中获取待处理文件列表。

### 步骤2：根据文件类型选择解析策略

#### 对于文档文件（docx, pdf, txt, md）：
使用 `read_file` 工具读取文件内容，提取：
- 标题结构
- 正文段落
- 表格数据（转换为Markdown表格格式）
- 列表内容

#### 对于图片文件：
使用 `read_file` 工具（支持图片）读取图片，分析：
- 图片类型（截图、流程图、UI设计图等）
- 图片中的文字内容
- 图片描述的功能或流程

#### 🆕 对于CSS设计稿文件（Figma导出）：
使用 `read_file` 工具读取CSS文件（可能需要分段读取大文件），解析：

**解析策略**：

1. **页面/模块结构识别**
   - 从类名的命名规律识别页面层级（如 `01-xxx`、`02-xxx` 前缀）
   - 从嵌套关系判断父子组件关系
   ```css
   /* 通用模式：编号前缀表示页面/模块 */
   .页面A { ... }
   .页面A .组件1 { ... }
   ```

2. **组件识别**
   - 从类名提取组件名称（通常是中文或有意义的命名）
   - 从CSS注释中提取组件说明
   ```css
   /* {组件名称} */
   .{组件类名} { ... }
   ```

3. **交互逻辑提取**
   - 重点扫描 CSS 注释，提取交互说明文字
   - 关注包含"点击"、"触发"、"打开"、"关闭"、"跳转"等动词的注释
   - 关注包含数字序号（如 `1.`、`2.`）的流程说明
   ```css
   /* 常见交互注释模式 */
   /* 1.点击xxx → 执行xxx */
   /* 排序逻辑：A > B > C */
   /* 触发条件：xxx时显示 */
   ```

4. **状态变体识别**
   - 从类名识别 UI 状态（常态、hover、active、disabled、selected 等）
   - 识别业务状态（如"已完成"、"进行中"、"已锁定"等）
   ```css
   /* 通用状态命名 */
   .组件-常态 { ... }
   .组件-hover { ... }
   .组件:hover { ... }
   .组件-disabled { ... }
   ```

5. **视觉规范提取**
   - 提取关键颜色值（主题色、背景色、文字色、边框色）
   - 提取字号、行高、间距
   - 提取圆角、阴影等样式
   ```css
   /* 关注的样式属性 */
   color: {值};
   background: {值};
   font-size: {值};
   border-radius: {值};
   padding/margin: {值};
   ```

6. **边界条件识别**
   - 从注释或占位符文本提取限制条件
   - 关注"最多"、"最少"、"上限"、"位数"等关键词
   ```css
   /* 常见边界条件模式 */
   /* 请输入xxx（N位数） */
   /* 上限N字/N个 */
   /* 最多显示N条 */
   ```

7. **文案提取**
   - 提取所有中文文案（按钮文字、提示文字、占位符）
   - 关注 `content`、注释中的引号内容
   ```css
   /* 文案来源 */
   content: "xxx";
   /* 占位符：请输入xxx */
   /* 提示：xxx */
   ```

## 特殊处理规则

### 表格处理
1. 保持表格的行列结构
2. 识别合并单元格
3. 提取表头信息

### 图片处理
1. 优先识别UI截图和流程图
2. 对于包含文字的图片，执行OCR提取
3. 对于流程图，描述流程步骤
4. **对可见UI元素进行完整描述，允许基于元素推断功能但必须标记【待确认】**

### UI控件逐项扫描（重要！）

**对于每张UI截图，必须逐项扫描以下控件类型，避免遗漏：**

| 控件类型 | 扫描要点 | 推断功能示例 |
|----------|----------|--------------|
| 输入框 | 搜索框、文本框、密码框、数字输入 | 搜索功能【待确认】、密码设置【待确认】 |
| 按钮 | 所有可点击按钮，包括图标按钮 | 按钮对应的操作功能 |
| 列表 | 列表项的结构、每项包含的元素 | 列表项的操作功能 |
| 弹窗 | 弹窗内的所有元素 | 弹窗触发和关闭逻辑 |
| 图标 | 刷新、设置、筛选、排序等图标 | 刷新功能【待确认】、筛选功能【待确认】 |
| 标签/Tab | Tab切换项 | Tab切换功能 |
| 状态标签 | 状态指示器、角标 | 状态变化逻辑【待确认】 |

3. CSS文件解析重点关注注释和类名，而非样式值本身

## 🚨 大文件分段读取规则（强制执行）

### CSS 文件分段读取策略

**背景**：Figma 导出的 CSS 文件通常非常大（10000-100000+ 行），单次 `read_file` 无法读取完整内容。

**强制规则**：

1. **首次尝试读取**：
   - 使用 `read_file` 不带 `limit` 参数读取
   - 如果返回 "File content exceeds maximum allowed characters" 错误，则进入分段读取模式

2. **分段读取模式**（强制执行）：
   ```
   每次读取: 500-1000 行
   重叠行数: 10 行（确保跨段内容不丢失）
   ```

   执行流程：
   ```
   第1次: read_file(offset=1, limit=1000)
   第2次: read_file(offset=991, limit=1000)  # 重叠10行
   第3次: read_file(offset=1981, limit=1000)
   ... 循环直到文件末尾
   ```

3. **终止条件**：
   - 读取返回的行数 < limit 参数
   - 或遇到文件结束标志

4. **逐段解析，增量汇总**：
   - 每读取一段，立即提取该段中的：
     - CSS 注释（`/* ... */`）
     - 中文文案
     - 交互逻辑描述
     - 页面/模块标识
   - 将提取结果追加到汇总结果中
   - **禁止**等待所有段落读取完毕后再解析

5. **进度报告**：
   每读取 5000 行，输出一次进度：
   ```
   [进度] 已读取 5000/50000 行 (10%)，已提取 XX 个页面、XX 条交互逻辑
   ```

### 分段读取代码示例

```python
# 伪代码示意
offset = 1
limit = 1000
overlap = 10
all_comments = []
all_interactions = []

while True:
    content = read_file(filepath, offset=offset, limit=limit)
    
    # 解析当前段
    comments = extract_comments(content)
    interactions = extract_interactions(content)
    all_comments.extend(comments)
    all_interactions.extend(interactions)
    
    # 检查是否到达文件末尾
    if len(content.split('\n')) < limit:
        break
    
    # 移动到下一段（带重叠）
    offset += limit - overlap
```

### 关键信息提取优先级

由于 CSS 文件很大，按以下优先级提取关键信息：

| 优先级 | 提取内容 | 识别模式 |
|--------|----------|----------|
| P0 | 页面/模块标题 | `/* 轻度违规 ... */`、`/* 主态禁止xxx */` 等描述性注释 |
| P0 | 交互逻辑 | 包含"点击"、"触发"、"显示"、"跳转"、"弹窗"等动词的注释 |
| P0 | 状态说明 | 包含"主态"、"客态"、"hover"、"disabled"等状态词的注释 |
| P1 | 边界条件 | 包含"N位数"、"最多"、"上限"等限制词的注释 |
| P1 | 提示文案 | `/* 您的账号已被xxx */`、`/* 请输入xxx */` 等用户提示 |
| P2 | 视觉规范 | 关键颜色值、字号（仅在需要时提取）|
