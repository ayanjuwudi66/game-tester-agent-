# 文件扫描与识别 Skill

## 功能概述
此skill用于扫描指定目录，识别并分类所有支持的文件类型，为后续的多模态处理提供文件清单。

## 使用场景
当用户需要处理一个文件夹中的需求文档时，首先调用此skill获取文件列表和分类信息。

## 支持的文件类型
- **文档类**: `.docx`, `.pdf`, `.txt`, `.md`
- **图片类**: `.png`, `.jpg`, `.jpeg`, `.gif`, `.bmp`, `.webp`
- **设计稿类**: `.css` (Figma CSS导出)

### 🆕 CSS 设计稿说明
从 Figma 导出的 CSS 文件（选择 "CSS (All Layers)"）包含完整的交互设计信息：
- **CSS 注释**：包含组件名称、中文文案、交互说明
- **层级结构**：反映页面组成和组件关系
- **样式属性**：包含颜色、字体、间距等视觉规范

**CSS 文件相比图片的优势**：
- ✅ 不依赖图像识别，避免幻觉
- ✅ 中文文案完整无遗漏
- ✅ 交互逻辑通过注释明确描述
- ✅ 视觉规范（颜色、尺寸）精确可提取

## 执行流程

### 步骤1：获取目标目录
向用户确认需要扫描的目录路径。如果用户未指定，使用默认路径 `./file/`

### 步骤2：扫描目录
使用 `list_dir` 工具扫描指定目录下的所有文件（单层扫描）。

### 步骤3：文件分类
根据文件扩展名将文件分为以下类别：
- `documents`: 文档文件（docx, pdf, txt, md）
- `images`: 图片文件（png, jpg, jpeg, gif, bmp, webp）
- `design_files`: 设计稿文件（css from Figma）
- `unknown`: 未知类型文件

### 步骤4：创建归档目录
**重要**：根据需求文件名和任务创建日期，创建归档目录用于存放所有输出结果。

归档目录命名规则：
```
output/{需求文件名（不含扩展名）}_{YYYYMMDD}/
```

示例：
```
output/G089-MS5-首页推荐功能_20260216/
```

使用 `execute_command` 创建归档目录：
```bash
mkdir -p "output/{需求文件名}_{日期}"
```

### 步骤5：输出文件清单
以结构化格式输出扫描结果：

```markdown
## 文件扫描结果

**扫描目录**: {目录路径}
**扫描时间**: {当前时间}
**文件总数**: {总数}
**归档目录**: {归档目录路径}

### 文档文件 ({数量})
| 序号 | 文件名 | 类型 | 路径 |
|------|--------|------|------|
| 1 | xxx.docx | Word文档 | /path/to/file |

### 图片文件 ({数量})
| 序号 | 文件名 | 类型 | 路径 |
|------|--------|------|------|
| 1 | xxx.png | PNG图片 | /path/to/file |

### 设计稿文件 ({数量})
| 序号 | 文件名 | 类型 | 来源 | 路径 |
|------|--------|------|------|------|
| 1 | xxx.css | CSS | Figma导出 | /path/to/file |

### 未识别文件 ({数量})
| 序号 | 文件名 | 路径 |
|------|--------|------|
```

## 归档目录结构
后续skill将在归档目录下生成以下文件：
```
output/{需求文件名}_{YYYYMMDDHHmm}/
├── 需求整理报告.md
├── 功能点列表.md
├── 测试点列表.md
├── 测试用例_模块/
│   └── {模块}.jsonl
├── {需求文件名}_{YYYYMMDDHHmm}.csv
├── 测试用例聚合报告.md
├── 评审报告.md            （可选）
└── temp/
    ├── _stats.json
    ├── _validate_report.json
    ├── _progress.json
    └── _review_data.json（可选）
```

## 注意事项
1. 当前版本仅支持单层目录扫描
2. 文件类型判断基于扩展名，不检查实际文件内容
3. **必须创建归档目录**，后续所有输出都存放在该目录下
4. 扫描结果和归档信息需要传递给后续skill使用

## 🚨 大文件预警机制

### CSS 文件大小预检

Figma 导出的 CSS 文件通常非常大（10000-100000+ 行），需要在扫描阶段进行预警。

**执行步骤**：

1. **获取文件大小**：
   使用 `execute_command` 获取 CSS 文件行数：
   ```powershell
   # Windows PowerShell
   (Get-Content "{文件路径}" | Measure-Object -Line).Lines
   ```
   ```bash
   # Linux/Mac
   wc -l "{文件路径}"
   ```

2. **大文件标记**：
   - 超过 5000 行：标记为 `[大文件]`
   - 超过 20000 行：标记为 `[超大文件]`
   - 超过 50000 行：标记为 `[巨型文件]`

3. **输出格式调整**：

```markdown
### 设计稿文件 ({数量})
| 序号 | 文件名 | 类型 | 行数 | 大小标记 | 路径 |
|------|--------|------|------|----------|------|
| 1 | xxx.css | CSS | 50000 | [超大文件] | /path/to/file |
```

4. **后续处理提示**：
   
   在扫描结果末尾添加提示：
   ```markdown
   ### ⚠️ 大文件处理提示
   
   检测到以下大文件，后续 `multimodal-parser` 将采用分段读取策略：
   
   | 文件 | 行数 | 预计分段数 | 建议读取方式 |
   |------|------|------------|--------------|
   | xxx.css | 50000 | 50 段 | 每段 1000 行，重叠 10 行 |
   
   **注意**：大文件解析耗时较长，请耐心等待完整解析完成。
   ```
