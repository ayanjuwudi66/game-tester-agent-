# 边界场景用例生成 Skill

## 🚨 前置步骤（必须最先执行）

**在生成任何用例之前，必须加载共享规范 skill：**

```
use_skill: testcase-conventions
# 加载后按 SKILL.md §二加载策略读取（弱基座回落）
read_file: references/_shared_conventions.md
```

该文件包含：8列格式规范、分类定义、6条撰写规范、UI排除规则、数值具体化规范、追加工具约束。**以下所有步骤均在遵守共享规范的前提下执行。**

---

## 🚨 最高优先级约束

**本 Skill 只负责生成 BJ（边界场景）分类的测试用例。**

- ✅ 允许的分类：BJ
- ❌ 禁止的分类：HX、FHX、ZD、YC、FCG、BL（这些由其他 Skill 负责）

---

## 核心原则：每个边界值必须独立成用例

```
示例：测试点「验证房间名长度边界」→ 展开为多条 BJ 用例：
├─ 用例1：输入空房间名
├─ 用例2：输入1个字符的房间名
├─ 用例3：输入9个字符的房间名（临界值-1）
├─ 用例4：输入10个字符的房间名（临界值）
└─ 用例5：尝试输入第11个字符（超限）
```

---

## 执行流程

### 步骤1：读取测试点五列表格（强制）

从测试点列表的「适用分类」列筛选含 BJ 的测试点，**这些测试点必须生成 BJ 用例**。同时读取「展开说明」列获取 BJ 展开线索。

**🚨 降级展开逻辑（当展开说明缺失或笼统时）**：

如果某测试点的「展开说明」中 BJ 部分为空或过于笼统（如仅写"BJ:边界"），则根据测试点描述按以下通用模板自行识别边界展开方向：

```
BJ 通用降级展开模板：
├── 涉及输入框 → 空值/1位/临界-1/最大/超限/特殊字符
├── 涉及列表/数量 → 空列表/单项/临界-1/满载/超载
├── 涉及数值 → 零值/最小值/最大值/临界值
├── 涉及密码 → 空/1位/临界-1/正好/超限
├── 涉及配置参数 → 必填缺失/类型错误/关联缺失/字段越界
├── 涉及日期时间 → 非法日期/格式异常/空值/跨时区
└── 涉及比例/百分比 → 0%/100%/超限/负值/临界精度
```

**覆盖率检查**（生成完用例后执行）：
```
□ 逐个检查适用分类包含BJ的测试点
□ 每个测试点至少有1条BJ用例覆盖（数量标准参见 `_shared_conventions.md §11`）
□ 未覆盖的测试点需补充用例或说明原因
```

### 步骤2：识别边界场景类型

```
□ 输入框 → 空输入、最大长度、超长输入、边界长度
□ 列表 → 空列表、单项、满载（如8项）、超过上限；多维度时追加笛卡尔积极端组合
□ 数值 → 最小值、最大值、0值、负值、临界值
□ 密码 → 位数不足、位数正好、位数超出
□ 配置参数 → 必填缺失、类型错误、关联ID不存在、字段越界
□ 日期时间 → 非法日期、格式异常、空值、跨时区
□ 比例/百分比 → 0%、100%、超过100%、负比例
□ 字符类型 → 纯数字、纯字母、特殊字符、表情、空格、混合
□ 状态 → 首次/非首次操作、单个/多个对象、重复操作
□ 时序 → 操作前/操作中/操作后
```

**🚨 配置表扫描（若需求含配置表结构，必须执行）**：从配置表字段提取可测边界——必填字段(缺失→空值)、数值字段(0/极值/负值)、ID字段(关联不存在)、时间字段(非法日期/空值)、枚举字段(无效值/越界值)。

### 步骤3：基于流程图的场景法识别（首要步骤）

从需求整理报告的「用户体验流程图」识别包含数值/数量/状态判断的分支节点，针对每个节点识别边界值：

```
分支节点示例：[房间数量<8] → 正常显示
├─ BJ用例1：房间数量为0个
├─ BJ用例2：房间数量为1个
├─ BJ用例3：房间数量为7个（临界值-1）
├─ BJ用例4：房间数量正好8个（临界值）
└─ BJ用例5：房间数量为9个（超限）
```

---

## 🚨🚨🚨 核心规范：数值必须具体、边界必须拆分

### 规范1：数值必须具体

| ❌ 模糊 | ✅ 具体 |
|---------|---------|
| 输入不足6位密码 | 输入1位密码"1" |
| 房间数量达到上限 | 房间数量正好8个 |
| 输入超过最大字符 | 输入17个字符（超过16字符限制） |

### 规范2：每个边界值必须独立成一条用例

|❌ 合并| ✅ 拆分 |
|---------|---------|
| 输入1-5位密码点击确认 | 用例1：输入1位密码 + 用例2：输入5位密码 |

**🚨 复合边界禁词清单（`case_desc`/`steps` 中绝对禁止出现）：**

以下表达形式均属"复合边界"——在单条用例中包含多个边界值，必须拆分为独立用例：

|❌ 禁止的复合边界写法 | ✅ 正确的独立用例写法 | 说明 |
|---|---|---|
| 旋转角度设为 `-180°/360°` | 用例1：旋转角度设为 -180°；用例2：旋转角度设为 360° |斜杠分隔的多值|
| 密码长度为 `空/1位` | 用例1：密码为空；用例2：密码为1位 | 状态/数值并列 |
| 输入`最小/最大`字符 | 用例1：输入最小字符数；用例2：输入最大字符数 | 极值并列 |
| 房间数量为 `0/8/9`个 | 用例1：0个；用例2：8个；用例3：9个 | 多值枚举 |
| `开启或关闭`时验证 | 用例1：开启状态验证；用例2：关闭状态验证 | 状态并列 |

**禁用词模式**（出现在 `case_desc` 或 `steps` 中即触发 validate 警告）：
- 两个数值/状态用`/` 分隔且两侧均为边界值（如 `-180°/360°`、`空/1位`）
- `最小/最大`、`开启/关闭`、`有/无`（用于描述边界状态时）

## 边界用例模板

**输入框边界：** 空值 → 1位 → 临界-1 → 最大 → 超限 → 特殊字符

| 边界类型 | 示例（必须写明具体数值） |
|----------|------------------------|
| 空值边界 | 清空房间名后保存 |
| 最小边界-1位 | 输入1个字符"测"的房间名 |
| 临界边界 | 输入9个字符的房间名（上限10） |
| 最大边界 | 输入正好10个字符的房间名 |
| 超限边界 | 尝试输入11个字符的房间名 |
| 特殊边界 | 输入"@#$%"等符号 |

**列表边界：** 空列表 → 单项 → 临界值-1 → 满载 → 超载

| 边界类型 | 示例 |
|----------|------|
| 空列表 | 房间数量为0个时查看列表 |
| 单项 | 房间数量为1个时的列表显示 |
| 临界值-1 | 房间数量正好7个时（上限8个） |
| 满载 | 房间数量正好8个时的显示 |
| 超载 | 房间数量为9个时的滚动显示 |

**🚨 笛卡尔积极端用例（多维度列表/数值边界时触发）：**

**触发条件**：同一功能点/页面涉及 ≥2 个独立数值维度各有上限时，必须额外生成极端值组合用例。

**生成规则**：
1. 识别各维度的极端值：空(0) / 满载(N) / 超载(N+1)
2. 取各维度极端值中**最有风险的组合**（非全排列）
3. **硬限：笛卡尔积极端用例不超过 4 条**
4. 若某组合在逻辑上不可能发生，标注为"配置矛盾容错"

**笛卡尔积用例示例**（商品列表：维度A=商品数/页上限20，维度B=每商品规格数上限10）：

| 维度A（商品数） | 维度B（规格数） | 测试意图 |
|:---:|:---:|------|
| 满载（20） | 满载（10） | 双维度满载时渲染性能和布局 |
| 超载（21） | 超载（11） | 双维度同时溢出时的处理逻辑 |
| 空（0） | 满载（10） | 无主体但子维度满载时的容错 |
| 满载（20） | 空（0） | 有主体但子维度为空时的展示 |

**笛卡尔积用例模板**：
```
维度识别：
- 维度A：{名称}，上限={N1}
- 维度B：{名称}，上限={N2}

极端组合（选取最有风险的≤4条）：
├─ 用例1：A满载({N1}) × B满载({N2}) → 验证{最大负载/渲染}
├─ 用例2：A超载({N1+1}) × B超载({N2+1}) → 验证{双溢出处理}
├─ 用例3：A空(0) × B满载({N2}) → 验证{空主体容错}
└─ 用例4：A满载({N1}) × B空(0) → 验证{子维度为空展示}
```

**数值边界：** 零值 → 最小值 → 最大值 → 临界值

| 边界类型 | 示例 |
|----------|------|
| 零值 | 金额为0元时提现 |
| 最小值 | 购买数量为1时 |
| 最大值 | 金额为999999元时 |

**密码边界（6位示例）：** 空 → 1位 → 临界-1 → 正好 → 超限

| 边界类型 | 用例描述 |
|----------|----------|
| 空密码 | 密码为空时点击确认 |
| 1位密码 | 输入1位密码"1"点击确认 |
| 5位密码 | 输入5位密码"12345"点击确认 |
| 6位密码 | 输入正好6位密码"123456" |
| 超限密码 | 尝试输入第7位密码时的限制 |

**配置参数边界：**

| 边界类型 | 示例 |
|----------|------|
| 必填缺失 | 商品ID为空时加载商品列表 |
| 类型错误 | 限购次数配置为"abc"（应为整数） |
| 关联缺失 | 关联ID指向的记录不存在 |
| 字段越界 | 排序编号配置为负数 |

**日期时间边界：**

| 边界类型 | 示例 |
|----------|------|
| 非法日期 | 配置2月30日为开始时间 |
| 格式异常 | 出现时间配置为空字符串 |
| 跨时区 | 跨日/跨时区时贩卖时间判断 |

**比例/百分比边界：**

| 边界类型 | 示例 |
|----------|------|
| 零比例 | 折扣比例为0%时显示 |
| 满比例 | 折扣比例为100%时显示 |
| 超限比例 | 折扣比例为150%时显示 |
| 负比例 | 折扣比例为-10%时容错 |
| 临界精度 | 比例为最小精度值（如0.01%/99.99%）时精度校验 |

## 质量检查点

```
□ 输入框相关测试点至少有3-5条BJ用例（空/最小/临界/最大/超限）
□ 列表相关测试点至少有3-4条BJ用例（空/单项/满载/超载）
□ 数值相关测试点至少有3-4条BJ用例（零值/最小/最大/超限）
□ 禁止边界值合并："输入1-5位密码"→拆分为"输入1位"+"输入5位"
□ 所有数值已具体化，无"若干"等模糊词
□ 每个适用分类含BJ的测试点至少有1条BJ用例
□ 🚨 多维度识别：检查是否存在≥2个独立数值维度，如有则必须生成笛卡尔积极端用例
□ 🚨 笛卡尔积用例数量≤4条，且每条标注了具体维度值和测试意图
```

**自检命令：搜索以下模糊词汇：**
- "不足X位" → 应拆分为具体位数的独立用例
- "1-N位" → 应拆分为多条用例
- "少于/多于" → 应写明具体数值
- "仅测试端点值（0/1/999999）" → 若测试点含明确上限/下限，必须补临界值-1 和 临界值+1 的独立用例

## JSONL 输出格式（append 模式）

将生成的每条用例逐行 append 到 `测试用例_模块/{模块名}.jsonl`（UTF-8 无 BOM）：

```python
import json
from pathlib import Path

out_file = Path(archive_dir) / "测试用例_模块" / f"{module_name}.jsonl"
out_file.parent.mkdir(parents=True, exist_ok=True)
with open(out_file, "a", encoding="utf-8") as f:      # 硬约束：mode='a'
    for case in cases:
        f.write(json.dumps(case, ensure_ascii=False) + "\n")
```

**JSONL 示例**：
```jsonl
{"submodule":"创建房间","feature_point":"玩家在游戏主页面创建新房间，支持公开/密码两种模式","testpoint":"验证房间名长度限制","case_desc":"房间名恰好为10个字符（上限值）","precondition":"已进入创建房间页面","steps":"1.输入10个字符的房间名\n2.点击创建","expected":"1.输入被完整接受\n2.房间创建成功","category":"BJ"}
{"submodule":"创建房间","feature_point":"玩家在游戏主页面创建新房间，支持公开/密码两种模式","testpoint":"验证房间名长度限制","case_desc":"房间名为11个字符（超上限）","precondition":"已进入创建房间页面","steps":"1.输入11个字符的房间名\n2.点击创建","expected":"1.超出部分被截断或提示\n2.按提示处理","category":"BJ"}
```

**字段规范**：
- **必填字段**：`submodule / feature_point / testpoint / case_desc / precondition / steps / expected / category`
- **`category` 只能填 `BJ`**（本 skill 负责的分类）
- **`module` 可省略**：由渲染层用文件名兜底
- **`feature_point` 必填**：值 = 测试点表格**第 2 列**「功能点描述」；**禁止留空、禁止依赖渲染层反查**
- **`testpoint` 与拆分器输出保持一致**：不重命名、不重排
- **多步骤用 `\n` 换行**（禁 `<br>`）
- 详细规范参见 `_shared_conventions.md §8.3`

## 注意事项

1. **只生成 BJ 分类的用例**
2. 异常操作用例（YC）由 `testcase-exception` 负责
3. 功能遍历用例（BL）由 `testcase-traverse` 负责
4. 核心流程用例由 `testcase-core` 负责
5. 中断场景用例由 `testcase-interrupt` 负责
6. **必须使用 `open(mode='a')` 追加 JSONL**，禁止 `write_to_file` 覆盖已有文件；禁止 `replace_in_file` 修改 JSONL
7. 保持模块和子模块命名一致性
