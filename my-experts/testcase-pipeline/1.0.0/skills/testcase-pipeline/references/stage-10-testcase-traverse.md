# 功能遍历用例生成 Skill

## 🚨 前置步骤（必须最先执行）

**在生成任何用例之前，必须加载共享规范 skill：**

```
use_skill: testcase-conventions
# 加载后按 SKILL.md §二加载策略读取（弱基座回落）
read_file: references/_shared_conventions.md
```

该文件包含：8列格式规范、分类定义、6条撰写规范、UI排除规则、数值具体化规范、追加工具约束。**以下所有步骤均在遵守共享规范的前提下执行。**

---

## 🚨 最高优先级约束

**本 Skill 只负责生成 BL（功能遍历）分类的测试用例。**

- ✅ 允许的分类：BL
- ❌ 禁止的分类：HX、FHX、ZD、BJ、YC、FCG（这些由其他 Skill 负责）

---

## ⚠️ BL 与其他分类的区分

| 场景 | 分类 | 说明 |
|------|------|------|
| 输入全汉字房间名 | **BL** | 验证不同输入类型的正确处理 |
| 输入超长房间名 | **BJ** | 边界值测试 |
| 输入非法字符房间名 | **YC** | 异常输入测试 |
| 正常输入房间名并创建 | **HX** | 核心功能验证 |

---

##核心原则：同一功能的多种输入/操作组合

```
示例：测试点「验证房间名输入组合」→ 展开为多条 BL 用例：
├─ 用例1：输入纯中文房间名
├─ 用例2：输入纯英文房间名
├─ 用例3：输入纯数字房间名
├─ 用例4：输入中英混合房间名
└─ 用例5：输入带特殊字符房间名
```

**🚨 聚合词禁词清单（`case_desc`/`steps` 中绝对禁止出现）：**

BL 用例禁止在单条用例中使用聚合表达，每个具体输入组合必须独立成一条用例：

| ❌ 禁止的聚合写法 | ✅ 正确的拆分写法 | 说明 |
|---|---|---|
| 每档下遍历全部/图片/视频/音频页签页数 | 用例1：图片页签翻页；用例2：视频页签翻页；... | 遍历+全部 |
| 遍历所有页签类型 | 用例1：图片页签；用例2：视频页签；用例3：音频页签 | 遍历+枚举 |
| 每种房间类型下的创建流程 | 用例1：公开房间创建；用例2：私密房间创建 | 每种+枚举 |
| 全部字体样式效果验证 | 用例1：粗体；用例2：斜体；用例3：下划线 | 全部+枚举 |
| 各档位音量调节 | 用例1：最低档；用例2：中等档；用例3：最高档 | 各档+遍历 |

**禁用词模式**（出现在 `case_desc` 或 `steps` 中即触发 validate 警告）：
- `每档`、`每种`、`遍历`（后接宾语）、`全部.*页签`、`所有.*类型`、`各.*档`
- "/"分隔多个并列输入类型（如"中文/英文/数字输入"），应拆为独立用例

## 执行流程

### 步骤1：读取测试点五列表格（强制）

从测试点列表的「适用分类」列筛选含 BL 的测试点，**这些测试点必须生成 BL 用例**。同时读取「展开说明」列获取 BL 展开线索。

**🚨 降级展开逻辑（当展开说明缺失或笼统时）**：

如果某测试点的「展开说明」中 BL 部分为空或过于笼统（如仅写"BL:遍历"），则根据测试点描述按以下通用模板自行识别遍历展开方向：

```
BL 通用降级展开模板：
├── 涉及输入框 → 全汉字/全英文/纯数字/中英混合/Emoji/带空格/标点符号
├── 涉及操作方式 → 键盘输入/粘贴输入/语音输入（如支持）
├── 涉及格式 → 全大写/全小写/混合大小写
├── 涉及选项 → 遍历各可选项/不同组合/默认值
└── 涉及搜索 → 精确匹配/模糊匹配/大小写/前缀/后缀/中间匹配
```

**覆盖率检查**（生成完用例后执行）：
```
□ 逐个检查适用分类包含BL的测试点
□ 每个测试点至少有1条BL用例覆盖（数量标准参见 `_shared_conventions.md §11`）
□ 未覆盖的测试点需补充用例或说明原因
```

### 步骤2：识别遍历场景类型

```
□ 输入类型遍历 → 全汉字、全英文、数字、混合、Emoji、空格、标点
□ 操作方式遍历 → 键盘输入、粘贴输入、语音输入、拖拽
□ 数据格式遍历 → 不同编码、不同格式、大小写
□ 选项遍历 → 多个可选项、不同组合
□ 状态遍历 → 不同初始状态下执行同一操作
```

## BL 遍历用例模板（4 类）

**输入类型遍历：**

| 遍历类型 | 示例 |
|----------|------|
| 全汉字 | 输入全汉字房间名 |
| 全英文 | 输入英文房间名 |
| 纯数字 | 输入数字房间名 |
| 汉字+数字 | 输入汉字+数字房间名 |
| 英文+数字 | 输入英文+数字房间名 |
| Emoji | 输入Emoji房间名 |
| 带空格 | 输入带空格的房间名 |
| 标点符号 | 输入带标点的房间名 |

**操作方式遍历：**

| 遍历类型 | 示例 |
|----------|------|
| 键盘输入 | 键盘输入房间名 |
| 粘贴输入 | 复制粘贴房间名 |
| 语音输入 | 语音输入房间名（如支持） |

**格式遍历：**

| 遍历类型 | 示例 |
|----------|------|
| 全大写 | 输入全大写英文房间名 |
| 全小写 | 输入全小写英文房间名 |
| 混合大小写 | 输入混合大小写房间名 |

**选项遍历：**

| 遍历类型 | 示例 |
|----------|------|
| 单选项 | 选择不同的房间类型 |
| 多选项 | 选择不同的房间标签组合 |

## 质量检查点

```
□ 每个输入框都有：汉字、英文、数字、混合 输入遍历
□ 支持Emoji的输入框需要Emoji遍历
□ 支持粘贴的输入框需要粘贴输入遍历
□ 单选组件：遍历所有可选项
□ 多选组件：遍历典型组合
□ 若某测试点在BL分类下只有1条用例，检查展开说明是否暗示多种输入/操作类型
```

## JSONL 输出格式（append 模式）

将生成的每条用例逐行 append 到 `测试用例_模块/{模块名}.jsonl`（UTF-8 无 BOM）：

```python
import json
from pathlib import Path

out_file = Path(archive_dir) / "测试用例_模块" / f"{module_name}.jsonl"
out_file.parent.mkdir(parents=True, exist_ok=True)
with open(out_file, "a", encoding="utf-8") as f:      # 硬约束：mode='a'
    for case in cases:
        f.write(json.dumps(case, ensure_ascii=False) + "\n")
```

**JSONL 示例**：
```jsonl
{"submodule":"创建房间","feature_point":"玩家在游戏主页面创建新房间，支持公开/密码两种模式","testpoint":"验证房间名输入","case_desc":"房间名为纯中文字符","precondition":"已进入创建房间页面","steps":"1.输入\"欢乐游戏\"\n2.点击创建","expected":"1.显示正常\n2.创建成功","category":"BL"}
{"submodule":"创建房间","feature_point":"玩家在游戏主页面创建新房间，支持公开/密码两种模式","testpoint":"验证房间名输入","case_desc":"房间名为纯英文字符","precondition":"已进入创建房间页面","steps":"1.输入\"HappyRoom\"\n2.点击创建","expected":"1.显示正常\n2.创建成功","category":"BL"}
{"submodule":"创建房间","feature_point":"玩家在游戏主页面创建新房间，支持公开/密码两种模式","testpoint":"验证房间名输入","case_desc":"房间名含特殊符号","precondition":"已进入创建房间页面","steps":"1.输入\"Room-01_test\"\n2.点击创建","expected":"1.显示正常\n2.创建成功","category":"BL"}
```

**字段规范**：
- **必填字段**：`submodule / feature_point / testpoint / case_desc / precondition / steps / expected / category`
- **`category` 只能填 `BL`**（本 skill 负责的分类）
- **`module` 可省略**：由渲染层用文件名兜底
- **`feature_point` 必填**：值 = 测试点表格**第 2 列**「功能点描述」；**禁止留空、禁止依赖渲染层反查**
- **`testpoint` 与拆分器输出保持一致**：不重命名、不重排
- **多步骤用 `\n` 换行**（禁 `<br>`）
- 详细规范参见 `_shared_conventions.md §8.3`

## 注意事项

1. **只生成 BL 分类的用例**
2. BL 重点是"相同操作的不同输入类型"，不是边界值或异常输入
3. **必须使用 `open(mode='a')` 追加 JSONL**，禁止 `write_to_file` 覆盖已有文件；禁止 `replace_in_file` 修改 JSONL
4. 保持模块和子模块命名一致性
