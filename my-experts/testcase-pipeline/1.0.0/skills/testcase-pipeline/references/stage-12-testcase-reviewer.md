# 测试用例评审 Skill

## 功能概述
此skill对生成的测试用例进行全面评审，采用9维加权评审体系，通过6阶段Pipeline执行特征提取、量化评分和漏测识别，最终以Markdown格式输出评审报告到归档目录。

## 使用场景
在 `testcase-generator` skill完成测试用例生成后，调用此skill进行用例评审。

---

## 评审Pipeline总览

```
输入材料 → 阶段1:数据预处理 → 阶段2:特征提取(9维并行) → 阶段3:独立评分 → 阶段4:加权汇总 → 阶段5:漏测识别 → 阶段6:报告生成
```

---

## 阶段1：数据预处理

### 1.1 接收评审材料

收集以下材料进行评审：
- 原始需求文档内容
- 整理后的需求（来自 `requirement-organizer`）
- 功能点列表（来自 `feature-splitter`）
- 测试点列表（来自 `testpoint-splitter`）
- 测试用例CSV（来自 `testcase-generator`）
- **归档目录信息**（来自 `file-scanner`）

### 1.2 数据解析与索引构建

**解析CSV用例文件**：
- 提取所有用例行，标准8列格式：`模块/子模块/测试点描述/用例描述/前提条件/操作步骤/预期结果/用例分类`
- 跳过表头行，逐行解析
- 过滤空行和格式异常行

**解析需求材料**：
- 从需求整理报告提取所有需求点清单，标注类型（功能需求/业务规则/异常处理/UI需求/配置项）
- 从功能点列表提取：功能点ID + 描述 + 所属模块
- 从测试点列表提取：测试点ID + 描述 + 所属模块/子模块

**构建层级索引**：
```
模块 → 子模块列表 → 子模块下的测试点列表 → 测试点下的用例列表
```

### 1.3 基础统计

| 统计项 | 计算方式 |
|--------|----------|
| 用例总数 | CSV有效行数 |
| 模块数 | 去重模块列 |
| 子模块数 | 去重子模块列 |
| 测试点数 | 去重(模块+子模块+测试点描述) |
| 功能点数 | 功能点列表中的条目数 |
| 各分类用例数 | 按用例分类列分组计数 |

## 阶段1.5：🔬 预计算脚本执行（优化7）

> **目的**：将重复检测（余弦相似度）、统计分析（变异系数）等计算密集型逻辑从 LLM 模拟计算改为 Python 脚本精确计算，LLM 仅负责解读结果并撰写评审意见，提高评审精度。

**操作**：将以下脚本写出为 `{归档目录}/temp/_review_data.py`，执行后读取 `temp/_review_data.json` 结果。

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
_review_data.py
评审预计算脚本：相似度矩阵 + 分类统计 + 变异系数分析
依赖：pip install jieba（如不可用则退化为字符级处理）
"""
import os, re, csv, json, sys, io, math, glob
from collections import Counter, defaultdict

if sys.platform == 'win32':
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8', errors='replace')
    sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding='utf-8', errors='replace')

BASE_DIR = os.path.dirname(os.path.abspath(__file__))   # = {归档目录}/temp/
ARCHIVE_DIR = os.path.dirname(BASE_DIR)                # = {归档目录}

# 自动定位归档目录根部的 CSV 文件（动态命名，排除 _ 前缀的辅助文件）
csv_files = [f for f in glob.glob(os.path.join(ARCHIVE_DIR, "*.csv"))
             if not os.path.basename(f).startswith("_")]
CSV_FILE = csv_files[0] if csv_files else None

# ── 读取 CSV ──
rows = []
with open(CSV_FILE, encoding='utf-8-sig', newline='') as f:
    reader = csv.reader(f)
    header = next(reader, None)
    for r in reader:
        if len(r) >= 8:
            rows.append(r)

# ── 分词函数（优先 jieba，退化为字符级） ──
try:
    import jieba
    def tokenize(text):
        return list(jieba.cut(text, cut_all=False))
except ImportError:
    def tokenize(text):
        return list(text)

# ── TF-IDF 余弦相似度 ──
def cosine_sim(tokens_a, tokens_b):
    c_a, c_b = Counter(tokens_a), Counter(tokens_b)
    vocab = set(c_a) | set(c_b)
    dot = sum(c_a.get(t, 0) * c_b.get(t, 0) for t in vocab)
    norm_a = math.sqrt(sum(v**2 for v in c_a.values()))
    norm_b = math.sqrt(sum(v**2 for v in c_b.values()))
    return dot / (norm_a * norm_b) if norm_a and norm_b else 0.0

# ── 构建用例描述的 Token 列表 ──
descs = [r[3] for r in rows]  # *用例描述列
tokens_list = [tokenize(d) for d in descs]

# ── 高相似度对（>= 0.85） ──
similar_pairs = []
N = len(tokens_list)
for i in range(N):
    for j in range(i+1, N):
        sim = cosine_sim(tokens_list[i], tokens_list[j])
        if sim >= 0.85:
            similar_pairs.append({
                "row_a": i+2, "desc_a": descs[i],
                "row_b": j+2, "desc_b": descs[j],
                "similarity": round(sim, 3)
            })

# ── 分类统计 ──
CATEGORY_ORDER = ["HX", "FHX", "BL", "BJ", "YC", "FCG", "ZD"]
category_counts = Counter(r[7] for r in rows if r[7] in CATEGORY_ORDER)
total = len(rows)
category_stats = {k: {"count": category_counts.get(k, 0),
                       "ratio": round(category_counts.get(k, 0) / total * 100, 1) if total else 0}
                  for k in CATEGORY_ORDER}

# ── 模块分布变异系数 ──
module_counts = Counter(r[0] for r in rows)
vals = list(module_counts.values())
if vals:
    mean = sum(vals) / len(vals)
    variance = sum((v - mean)**2 for v in vals) / len(vals)
    cv = math.sqrt(variance) / mean if mean else 0
else:
    cv = 0

# ── 测试点展开率 ──
testpoint_groups = defaultdict(list)
for r in rows:
    key = (r[0], r[1], r[2])
    testpoint_groups[key].append(r[7])
expand_rates = {str(k): len(v) for k, v in testpoint_groups.items()}
avg_expand = sum(expand_rates.values()) / len(expand_rates) if expand_rates else 0

# ── 输出 JSON ──
result = {
    "total_cases": total,
    "category_stats": category_stats,
    "module_distribution": {k: v for k, v in module_counts.items()},
    "module_cv": round(cv, 3),
    "avg_expand_rate": round(avg_expand, 2),
    "similar_pairs_count": len(similar_pairs),
    "similar_pairs": similar_pairs[:20],  # 最多展示20对
    "testpoint_expand": expand_rates
}
out_path = os.path.join(BASE_DIR, "_review_data.json")  # → temp/_review_data.json
with open(out_path, 'w', encoding='utf-8') as f:
    json.dump(result, f, ensure_ascii=False, indent=2)

print(f"预计算完成：{total} 条用例，{len(similar_pairs)} 对高相似用例，平均展开率 {avg_expand:.2f}")
```

**执行命令：**
```powershell
python {归档目录}\temp\_review_data.py
```

**读取结果用于以下评审维度：**
- `similar_pairs` → 维度6（重复性）：直接使用相似度对，无需 LLM 模拟计算
- `module_cv` → 维度7（模块划分合理性）：变异系数 > 0.5 说明分布不均
- `avg_expand_rate` → 维度8（测试点拆分合理性）：< 2.5 说明展开不足
- `category_stats` → 维度9（分类正确性）：与目标占比对比

## 阶段2：特征提取（9维并行）

### 维度1：完整性（权重 18%）

**目标**：检查需求文档中每个需求点是否都有对应测试用例覆盖。

**特征提取方法**：

1. **功能点映射**：逐一取功能点列表中的每个功能点，在用例CSV中搜索是否有相同/相似模块下的用例覆盖该功能点的描述关键词
2. **测试点映射**：逐一取测试点列表中的每个测试点，在用例CSV的"测试点描述"列中查找是否有完全匹配或语义匹配的条目
3. **需求点映射**：从需求整理报告中提取的每个需求点，检查是否有对应用例覆盖

**量化评分公式**：

```
功能点覆盖率 = 有用例覆盖的功能点数 / 功能点总数 × 100
测试点覆盖率 = 有用例映射的测试点数 / 测试点总数 × 100
需求覆盖率   = 有用例覆盖的需求点数 / 需求点总数 × 100

完整性评分 = 功能点覆盖率 × 0.3 + 测试点覆盖率 × 0.4 + 需求覆盖率 × 0.3
```

**额外扣分规则**：
- 关键功能点（标注为P0/核心的）完全无覆盖：每个扣5分
- 需求文档中明确提到的业务规则无验证用例：每个扣3分

**评分映射表**：

| 覆盖情况 | 评分区间 |
|----------|----------|
| 所有关联的功能点、测试点、需求点均有用例覆盖 | 90-100 |
| 个别功能点/测试点缺少覆盖（≤3处） | 75-89 |
| 部分功能点/测试点缺少覆盖（4-8处） | 60-74 |
| 大量功能点/测试点未覆盖（>8处） | <60 |

---

### 维度2：可执行性（权重 14%）

**目标**：检查用例的操作步骤和预期结果是否可执行、可验证。

**特征提取方法**：

逐条检查每条用例的操作步骤和预期结果，提取以下4个特征：

**特征2.1 操作动词检出**：
- 检查操作步骤是否包含明确的操作动词
- **操作动词词典**：
  - 鼠标操作：点击/双击/右键/悬停/拖拽/滑动/滚动
  - 键盘操作：输入/粘贴/删除/按回车/按ESC/按Tab
  - 触屏操作：长按/轻触/捏合/放大
  - 导航操作：进入/切换/返回/跳转/查看/找到
  - 数据操作：选择/勾选/取消/保存/提交/上传/下载/添加/移除
  - 状态操作：刷新/断开/恢复/挂起/关闭/打开/折叠/展开
  - 确认操作：确认/验证/检查/观察/记录
- 计算方式：有操作动词的步骤数 / 总步骤数

**特征2.2 步骤编号率**：
- 检查操作步骤是否使用分步编号
- 有效编号格式：`1.2.3.` / `①②③` / `1、2、3、` / `步骤1/步骤2`
- 计算方式：有分步编号的用例数 / 总用例数

**特征2.3 预期可验证率**：
- 检查预期结果是否可量化验证
- **可验证的预期结果**：包含具体的状态描述、数值变化、页面跳转目标、UI元素变化、文案内容
- **不可验证的预期结果**：仅含"正常""正确""合适""成功""符合预期""无异常"等泛化描述
- 计算方式：预期结果可验证的用例数 / 总用例数

**特征2.4 前提充分率**：
- 检查前提条件是否完整且可复现
- **充分的前提条件**：明确了账号状态、页面位置、数据准备、环境配置
- **不充分的前提条件**：空值、仅写"无"、缺少关键状态说明
- 计算方式：前提条件充分的用例数 / 总用例数

**量化评分公式**：

```
可执行性评分 = 操作动词检出率×30 + 步骤编号率×20 + 预期可验证率×30 + 前提充分率×20
```

**评分映射表**：

| 可执行情况 | 评分区间 |
|------------|----------|
| 所有操作步骤清晰可执行，预期结果均可验证 | 90-100 |
| 个别用例步骤缺少动词或编号，预期结果基本可验证 | 75-89 |
| 部分用例步骤模糊，部分预期结果难以验证 | 60-74 |
| 大量用例步骤不可执行或预期结果无法验证 | <60 |

---

### 维度3：异常覆盖度（权重 13%）

**目标**：检查边界值、无效输入、异常处理等场景的覆盖率。

**特征提取方法**：

预定义9类异常场景，扫描所有用例（重点扫描BJ/YC/ZD分类）判断每类场景在各子模块中的覆盖情况：

**异常场景清单**：

| 序号 | 异常类型 | 检测关键词/模式 | 适用子模块特征 |
|------|----------|----------------|----------------|
| 1 | 空值/空字符串 | 空值/空字符串/不输入/清空/留空 | 含输入框/编辑功能的子模块 |
| 2 | 非法字符/特殊字符 | 特殊字符/非法字符/符号/注入/XSS/脚本 | 含文本输入的子模块 |
| 3 | 超长文本 | 超长/最大长度/超出限制/截断 | 含文本输入的子模块 |
| 4 | 数值边界 | 最小值/最大值/0/负数/极值 | 含数值配置的子模块 |
| 5 | 数量限制 | 刚好/上限/最多/最少/已满/≤/≥ | 含列表/数量限制的子模块 |
| 6 | 时间边界 | 超时/过期/倒计时/到期 | 含时间相关功能的子模块 |
| 7 | 网络异常 | 断网/网络中断/弱网/加载失败/网络异常 | 所有需要网络请求的子模块 |
| 8 | 权限/状态 | 未登录/无权限/不同角色/游客/不同状态 | 含权限控制的子模块 |
| 9 | 数据极端 | 空数据/大量数据/0条/1000条 | 含数据展示的子模块 |

**覆盖判定方法**：
1. 先识别每个子模块适用的异常类型（基于子模块功能特征）
2. 对每个适用的异常类型，检查该子模块下是否有对应用例覆盖
3. 不适用的异常类型不参与该子模块的覆盖率计算

**量化评分公式**：

```
各类覆盖率 = 该类有覆盖的适用子模块数 / 该类应覆盖的子模块数 × 100
总覆盖率 = Σ(各类覆盖率) / 9
异常覆盖度评分 = 总覆盖率
```

**额外扣分规则**：
- 安全相关异常（SQL注入/XSS/敏感信息泄露）缺失：每个扣10分
- 数据丢失风险场景（如保存中断、并发编辑）缺失：每个扣5分

**评分映射表**：

| 异常覆盖情况 | 评分区间 |
|-------------|----------|
| 边界值、异常输入、异常处理、状态场景均有充分覆盖 | 90-100 |
| 主要异常场景有覆盖，少数遗漏 | 75-89 |
| 异常覆盖不足，缺少重要边界/异常场景 | 60-74 |
| 缺少大部分异常场景覆盖 | <60 |

### 维度4：二义性（权重 9%）

**目标**：检查用例描述中是否存在模糊词、缺少量化、指代不明等问题。

**特征提取方法**：

逐条扫描操作步骤和预期结果文本，检测以下4类模糊表达：

**模糊词词典**：

| 类别 | 模糊词列表 | 示例 |
|------|-----------|------|
| 程度模糊词 | 合适/适当/较大/较小/较长/较短/较多/较少/很快/很慢/合理/充分/适当/基本/大致/差不多/差不多就行 | "加载较快" → 应量化为"加载时间≤3秒" |
| 选择模糊词 | 或/或者/可能是/也许/大概/似乎/有可能 | "显示成功或失败" → 应明确分别描述 |
| 指代模糊词 | 该按钮/相关页面/对应功能/其/此/上述/那个/这个 | "点击该按钮" → 应明确"点击确认按钮" |
| 不确定词 | 观察实际行为/视情况/看效果/待确认/TBD/未定/暂不/自行判断 | "视情况显示" → 应明确具体条件 |

**检测规则**：
1. 对每条用例的操作步骤和预期结果进行文本扫描
2. 匹配模糊词词典中的词汇（精确匹配 + 词根匹配）
3. 标记包含模糊词的用例及具体位置
4. 判断模糊严重程度：
   - **致命二义性**：预期结果含"或/或者"导致结果不唯一，含"观察/视情况"导致无法判定通过标准
   - **一般二义性**：操作步骤含指代词，描述中含程度模糊词

**量化评分公式**：

```
致命二义数 = 预期结果中存在致命二义性的用例条数
一般二义数 = 存在一般二义性的用例条数

二义性评分 = max(100 - 致命二义数 × 8 - 一般二义数 × 3, 0)
```

**评分映射表**：

| 二义性情况 | 评分区间 |
|-----------|----------|
| 所有描述清晰明确，无模糊词、无量化缺失、无指代不明 | 90-100 |
| 个别描述存在轻微模糊（≤3处） | 75-89 |
| 部分描述存在二义性问题（4-8处） | 60-74 |
| 大量描述模糊或指代不明（>8处） | <60 |

---

### 维度5：重复性（权重 9%）

**目标**：检测完全重复和高度相似的冗余用例。

**特征提取方法**：

采用TF-IDF + 余弦相似度算法检测相似用例对：

**算法流程**：

```
步骤1: 文档构建
  对每条用例，拼接以下字段为文档文本：
  文档i = 测试点描述 + " " + 用例描述 + " " + 操作步骤 + " " + 预期结果

步骤2: 文本预处理
  - 去除标点符号和编号（①②③、1.2.3.等）
  - 去除停用词（的/了/在/是/和/等）
  - 保留名词、动词、形容词等关键词

步骤3: 相似度计算
  对每对用例(i, j)计算语义相似度：
  - 提取两段文本的核心语义要素（操作对象、操作行为、预期状态）
  - 比对核心要素的重合度
  - 综合判断相似度分值（0-1.0）

步骤4: 相似度分级判定
  - 相似度 > 0.95 → "几乎重复"（操作对象和行为完全一致，仅数据参数不同）
  - 相似度 0.80-0.95 → "高度相似"（核心操作一致，细节略有差异）
  - 相似度 < 0.80 → "正常差异"

步骤5: 跨模块重复检查
  额外检查：不同模块下是否存在相同场景的重复覆盖
  - 对比不同模块中测试点描述相同/相似的用例对
```

**LLM模拟实现要点**：
- 由于不依赖外部Python库，由LLM逐对比较用例文本的语义相似度
- 比较时重点关注：操作对象是否一致、操作行为是否一致、预期结果是否一致
- 忽略无关差异：前提条件不同、参数值不同、用例分类不同

**量化评分公式**：

```
几乎重复对数 = 相似度 > 0.95 的用例对数
高度相似对数 = 相似度 0.80-0.95 的用例对数
跨模块重复对数 = 不同模块下的重复/相似用例对数

重复性评分 = max(100 - 几乎重复对数 × 10 - 高度相似对数 × 3 - 跨模块重复对数 × 5, 0)
```

**评分映射表**：

| 重复情况 | 评分区间 |
|----------|----------|
| 无重复用例，无高相似用例对 | 90-100 |
| 存在1-2对高相似用例（相似度>80%），可合并 | 75-89 |
| 存在3-5对高相似用例，或存在完全重复用例 | 60-74 |
| 存在大量重复或高度相似用例（>5对） | <60 |

### 维度6：模块划分合理性（权重 9%）

**目标**：检查模块是否为空、分布是否均匀、命名是否规范。

**特征提取方法**：

统计模块级指标，提取以下4个特征：

**特征6.1 空模块检测**：
- 检查是否存在模块名存在于功能点列表但CSV中无任何用例的模块
- 检查是否存在子模块下无测试点或用例的情况

**特征6.2 分布均匀度**：
- 计算各模块的用例数量
- 计算变异系数（CV = 标准差/均值）
- CV < 0.3 → 均匀；0.3 ≤ CV < 0.6 → 基本均匀；CV ≥ 0.6 → 不均匀

**特征6.3 命名规范率**：
- **命名规范规则**：
  - 使用名词性短语（如"搜索框功能""房间列表"）
  - 不混用动词/名词开头（如不应出现"点击按钮"和"按钮展示"混用）
  - 长度3-10字（过短如"搜索"不够具体，过长如"搜索框功能及搜索结果展示"过于冗余）
  - 不含特殊符号和编号
- 计算方式：命名规范模块数 / 总模块数 × 100

**特征6.4 层级清晰率**：
- 子模块应逻辑归属于其模块
- 不应出现子模块与模块名完全重复
- 不应出现子模块归属模糊（可属于多个模块）
- 计算方式：层级清晰的模块数 / 总模块数 × 100

**量化评分公式**：

```
空模块扣分 = 空模块数 × 15
分布均匀度 = max(1 - CV, 0) × 100    （CV为变异系数）
命名规范率 = 规范命名模块数 / 总模块数 × 100
层级清晰率 = 层级清晰模块数 / 总模块数 × 100

模块划分评分 = max(
  命名规范率 × 0.2 + 层级清晰率 × 0.2 + 分布均匀度 × 0.3 + 100 × 0.3 - 空模块扣分,
  0
)
```

**评分映射表**：

| 划分情况 | 评分区间 |
|----------|----------|
| 模块划分清晰、命名规范、分布均匀、无空模块 | 90-100 |
| 划分基本合理，个别模块命名不一致或分布略有偏斜 | 75-89 |
| 存在空模块或分布明显不均 | 60-74 |
| 模块划分混乱，存在大量空模块或命名不规范 | <60 |

### 维度7：测试点拆分合理性（权重 9%）

**目标**：检查测试点是否独立、粒度是否合理、描述是否充分。

**特征提取方法**：

统计测试点级指标，提取以下3个特征：

**特征7.1 独立性**：
- 每个测试点应能独立验证，不依赖其他测试点的执行结果
- **不独立的判定**：测试点描述中含"在前一步基础上""依赖XX用例执行""接上一步"等依赖表述
- 计算方式：无依赖的测试点数 / 总测试点数 × 100

**特征7.2 粒度合理性**（具体数量阈值参见 `_shared_conventions.md §11.3`）：
- **粒度过大判定**：一个测试点对应超过4条用例（说明测试点涵盖过多场景，应拆分）
- **粒度过小判定**：一个测试点仅有1条用例且描述极短（< 5字，说明测试点过于碎片化）
- **粒度合理**：一个测试点对应2–4条用例，或1条用例但描述充分（≥ 5字）
- 计算方式：粒度合理的测试点数 / 总测试点数 × 100

**特征7.3 描述充分性**：
- **描述充分判定**：测试点描述 ≥ 8字，能独立传达验证意图，不依赖上下文
- **描述不充分判定**：描述 < 8字，或描述为动词短语无法明确验证目标（如"功能测试""正常流程"）
- 计算方式：描述充分的测试点数 / 总测试点数 × 100

**量化评分公式**：

```
测试点拆分评分 = 独立性 × 0.3 + 粒度合理性 × 0.4 + 描述充分性 × 0.3
```

**评分映射表**：

| 拆分情况 | 评分区间 |
|----------|----------|
| 测试点独立、粒度合理、描述充分 | 90-100 |
| 个别测试点粒度偏大或偏小，描述基本充分 | 75-89 |
| 部分测试点存在依赖关系或粒度不合理 | 60-74 |
| 测试点拆分混乱，依赖严重或过度碎片化 | <60 |

### 维度8：用例分类正确性（权重 9%）

**目标**：检查用例分类是否符合规范（HX/FHX/BL/BJ/YC/FCG/ZD），是否与内容一致。

**特征提取方法**：

逐条检查用例的标注分类与实际内容的匹配关系。

**分类匹配判定规则**：

| 分类 | 判定条件（满足以下条件应标注为该分类） |
|------|--------------------------------------|
| **HX** | ①操作步骤描述的是核心主流程 ②前提条件为正常/默认状态 ③预期结果为正向成功 ④功能必经路径 |
| **FHX** | ①操作步骤描述的是非必经路径 ②或前提条件为特殊/非默认状态 ③或预期结果为次要功能验证 ④用户不一定触发的功能 |
| **BL** | ①操作步骤包含多种输入组合/参数遍历 ②或含"依次""逐一""分别""不同"等遍历关键词 ③同一操作的多种合法参数测试 |
| **BJ** | ①用例描述/前提条件含边界关键词：刚好/恰好/临界/最大/最小/≤/≥/0值/空值/上限/下限 ②或测试数量为极值/临界值 ③边界值相关的场景 |
| **YC** | ①操作步骤含异常行为关键词：快速/连续/同时/并发/注入/攻击/恶意/自己操作自己 ②或前提条件为异常/非法状态 ③正常用户不会做的操作 |
| **ZD** | ①操作步骤含中断关键词：刷新/断开/切换后台/挂机/断网/关闭/杀死进程/最小化 ②或预期结果涉及状态恢复/数据保留 ③功能运行中被中断后恢复 |

**分类错误判定**：

| 标注分类 | 实际应分类 | 典型错误 |
|----------|-----------|----------|
| HX | BJ | 操作步骤测试的是边界值却标注为核心用例 |
| HX | YC | 操作步骤为异常操作却标注为核心用例 |
| BJ | YC | 操作为非法输入/注入攻击却标注为边界 |
| BL | FHX | 仅为非必经路径但无遍历组合却标注为遍历 |
| YC | BJ | 操作为边界值测试却标注为异常 |
| ZD | YC | 操作为异常操作但无中断恢复场景却标注为中断 |

**量化评分公式**：

```
分类匹配率 = 内容与标注分类一致的用例数 / 总用例数 × 100

分布偏差度计算：
  对每个分类i：
    偏离度i = max(实际占比i - 建议占比上限i, 0) + max(建议占比下限i - 实际占比i, 0)
  总偏差度 = Σ(偏离度i)

分类正确性评分 = 分类匹配率 × 0.6 + max(100 - 总偏差度 × 200, 0) × 0.4
```

**建议分类占比**：

| 分类 | 建议占比下限 | 建议占比上限 |
|------|-------------|-------------|
| HX | 20% | 30% |
| FHX | 15% | 25% |
| BL | 20% | 30% |
| BJ | 10% | 15% |
| YC | 5% | 10% |
| ZD | 5% | 10% |

**评分映射表**：

| 分类情况 | 评分区间 |
|----------|----------|
| 所有分类符合规范，内容与标注一致，分布合理 | 90-100 |
| 个别用例分类与内容不完全匹配（≤3条） | 75-89 |
| 部分用例分类错误，或分布明显偏离建议占比 | 60-74 |
| 大量用例分类错误，分布严重失衡 | <60 |

### 维度9：配置覆盖度（权重 10%）

**目标**：检查测试用例是否完整覆盖需求文档中的配置设计点和配置规则。

**特征提取方法**：

从需求文档中识别所有配置项，按4类配置模板分类提取：

**配置模板**：

| 配置类型 | 特征 | 提取示例 |
|----------|------|----------|
| **数值配置** | 含具体数值/范围/阈值的配置 | 最大数量=8、超时时间=30秒、文件大小≤10MB |
| **开关配置** | 含启用/禁用/显示/隐藏的配置 | 是否开启XX功能、XX开关、默认开启/关闭 |
| **枚举配置** | 含有限选项/类型的配置 | 排序方式=最新/最热、可见范围=公开/好友/私密 |
| **组合配置** | 多配置项联动生效的规则 | 开启A且关闭B时→XX表现、不同等级+不同权限组合 |

**配置规则提取**：
- 默认值规则：配置项的默认状态/默认值
- 生效条件：配置何时生效（即时/刷新后/下次进入）
- 配置约束：配置间的互斥/依赖关系
- 配置变更影响：修改配置后的影响范围

**量化评分公式**：

```
配置项覆盖率 = 有用例覆盖的配置项数 / 需求中配置项总数 × 100
配置规则覆盖率 = 有验证的配置规则数 / 配置规则总数 × 100
组合场景覆盖率 = 有覆盖的配置组合数 / 重要配置组合数 × 100

配置覆盖度评分 = 配置项覆盖率 × 0.4 + 配置规则覆盖率 × 0.3 + 组合场景覆盖率 × 0.3
```

**无配置项时**：若需求文档中确实不包含任何配置项，该维度评分 = 100（N/A标记为满分且不计入加权）

**评分映射表**：

| 配置覆盖情况 | 评分区间 |
|-------------|----------|
| 需求中所有配置项、规则、组合均有用例覆盖 | 90-100 |
| 主要配置项有覆盖，个别配置规则遗漏 | 75-89 |
| 配置覆盖不足，缺少重要配置项或规则验证 | 60-74 |
| 大部分配置项未覆盖 | <60 |

## 阶段5：漏测识别

### 5.1 漏测点识别策略

**基于需求对比**：
- 对比需求文档和测试用例，找出未覆盖的需求点 → **需求漏测**

**基于异常覆盖度分析**：
- 检查9类异常场景在各子模块的覆盖缺口 → **边界漏测 / 异常漏测**

**基于配置覆盖度分析**：
- 检查配置项、配置规则、配置组合的覆盖缺口 → **配置漏测**

**基于经验规则**：
- 检查常见遗漏场景（空值保存、敏感词、特殊字符、并发操作） → **场景漏测**

**基于分类覆盖**：
- 检查各用例分类(HX/FHX/BL/BJ/YC/FCG/ZD)是否有足够覆盖 → **分类漏测**

### 5.2 漏测点分类

| 漏测类型 | 说明 | 风险级别 |
|----------|------|----------|
| 需求漏测 | 需求点未被测试覆盖 | 高 |
| 异常漏测 | 异常情况未被处理 | 高 |
| 边界漏测 | 边界条件未被测试 | 中 |
| 场景漏测 | 特定场景未被考虑 | 中 |
| 配置漏测 | 配置项/规则未被验证 | 中 |
| 兼容漏测 | 兼容性场景遗漏 | 低 |

### 5.3 漏测点优先级判定

- **高风险**：需求漏测 + 异常漏测（涉及核心功能和数据安全）
- **中风险**：边界漏测 + 场景漏测 + 配置漏测（影响功能完整性）
- **低风险**：兼容漏测（影响范围有限）
