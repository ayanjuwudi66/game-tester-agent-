# PRD 标准化拆解 Skill

将一份PRD文档拆解为三个独立的Markdown文件，作为测试用例评审系统的输入。

## 拆解产物

| 序号 | 产物 | 用途 | 原则 |
|:---:|:---|:---|:---|
| 1 | 功能点文档 | D1覆盖度检查 + D3边界识别 | 全量，宁可冗余不可遗漏 |
| 2 | 配置设计文档 | D3配置字段边界值检查 | 仅提取有明确配置表格式+字段定义的内容 |
| 3 | UI元素文档 | D10 UI测试覆盖率检查 | 只关注可交互/可见的界面元素 |

## 执行流程

### Step 1: 文档解析

根据输入文件格式选择解析方式：

**docx 文件**：运行辅助脚本
```bash
python "{SKILL_DIR}/scripts/parse_docx.py" <input.docx> <output_dir>
```
输出 `prd_raw.md` + `prd_media/media/` 下的图片文件。

**md 文件**：直接读取，无需转换。图片路径从Markdown中提取。

### Step 2: 图片OCR

逐张读取 Step 1 提取的所有图片文件（使用 read_file 工具），提取其中的文字、结构、UI元素信息。

为每张图片记录：
- 图片编号（按文件名排序：image1, image2, ...）
- 内容类型标签：`业务流程` / `UI界面` / `配置表` / `概念图` / `混合`
- OCR提取的关键信息摘要

### Step 3: 内容分流

按以下规则将PRD原文和图片OCR内容分流到三个文档：

#### 分流判定矩阵

| 内容特征 | 功能点文档 | 配置设计文档 | UI元素文档 |
|:---|:---:|:---:|:---:|
| 业务逻辑/功能规则 | ✅ | — | — |
| 数值约束散落在需求描述中（如"限制7个汉字"） | ✅ | — | — |
| 有明确配置表格式 + 字段说明 | — | ✅ | — |
| 有配置文件样例或配置项说明段落 | — | ✅ | — |
| UI元素显示/隐藏/交互行为 | — | — | ✅ |
| 同时涉及业务逻辑和UI交互 | ✅ | — | ✅ |
| 流程图（业务流程） | ✅ | — | — |
| 界面交互示意图 | ✅(兜底) | — | ✅ |
| 配置表截图 | — | ✅ | — |

#### 配置设计文档的提取标准（严格）

**提取**：
- PRD有明确的配置表格式（如"XX配置表"）+ 字段说明（字段名、类型、取值范围等）
- PRD有配置文件样例或配置项说明段落（如"可配置项"表格）

**不提取**（归功能点文档）：
- 散落在需求描述中的数值约束（如"血量上限999"）
- 业务规则中的数值条件（如"取名限制7个汉字"）

### Step 4: 结构化输出

按 `references/` 目录下的模板格式生成三个Markdown文件。关键要求：

**功能点文档**（参考 `references/templates/template_features.md`）：
- 每个功能点必须有唯一编号（F-001, F-002, ...）
- 按PRD章节组织分组
- 每个功能点标注来源章节
- 图片OCR补充的功能点单独成节
- 末尾附功能点统计表

**配置设计文档**（参考 `references/templates/template_config.md`）：
- 每张配置表标注来源章节
- 每个字段标注类型、说明、取值范围
- PRD未明确定义取值范围的字段标注"PRD未明确定义"
- 末尾附配置字段追溯汇总表

**UI元素文档**（参考 `references/templates/template_ui.md`）：
- 每个元素有唯一编号（UI-001, UI-002, ...）
- 按元素类型分组（3D元素/HUD/弹窗/按钮/特效等）
- 每个元素标注来源（章节编号和/或图片编号）
- 附图片来源对照表
- 末尾附UI元素统计表

### Step 5: 质量校验

拆解完成后执行三项校验：

**校验1：功能点完整性** — 将功能点列表与PRD原文逐章节交叉对比
- 生成覆盖率（已覆盖章节数 / PRD总章节数）
- **覆盖率 < 95% 时触发警告**，列出遗漏章节并补充功能点
- 功能点文档不允许为空，若为空则报错终止

**校验2：配置字段追溯** — 检查每个配置字段是否标注了PRD来源
- 每个字段必须追溯到PRD具体章节
- 不可凭空增加PRD中不存在的字段
- 配置设计文档允许为空（PRD无配置设计时跳过）

**校验3：UI元素追溯** — 检查每个UI元素是否标注了来源
- 每个元素必须追溯到PRD章节或图片编号
- UI元素文档允许为空（纯后端PRD时跳过）

### Step 6: 输出校验报告

在输出目录生成 `拆解校验报告.md`，包含：
- 三项校验的结果（通过/警告/失败）
- 功能点覆盖率数值
- 各文档的统计数据（功能点数、配置字段数、UI元素数）

## 输出文件命名

```
<output_dir>/
├── PRD拆解_功能点文档.md
├── PRD拆解_配置设计文档.md
├── PRD拆解_UI元素文档.md
└── PRD拆解_校验报告.md
```

## 错误处理

- PRD文件为空或无法解析 → 报错终止
- 功能点文档为空 → 报错终止
- 配置设计文档为空 → 正常，标注"PRD无明确配置设计"
- UI元素文档为空 → 正常，标注"PRD无UI元素描述"
- 覆盖率 < 95% → 警告并补充遗漏功能点
